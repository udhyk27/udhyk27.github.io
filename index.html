문제 해결

01
블록체인 서버 이상 감지 및 Discord 알림 구축
Besu · Bash · node_exporter | blog ↗
›
상황
Hyperledger Besu 기반 프라이빗 블록체인을 VM에서 운영 중 Besu 프로세스 종료·RPC 멈춤·VM 다운이 발생했고, 직접 접속하기 전엔 상태를 알 수 없었음.
원인
VM 내부에서 자기 자신을 감시하면 VM이 죽을 때 모니터링도 함께 중단됨. VirtualBox NAT 환경의 주소 변환으로 방화벽 화이트리스트가 어긋났고, Rocky Linux의 SELinux 라벨 문제로 node_exporter 실행도 실패.
해결
감시를 별도 VM으로 분리해 ping·RPC·Peer 수·블록 생성·디스크를 점검. 상태 변경 시에만 Discord 알림을 보내도록 구성하고, tcpdump로 실제 출발지 IP를 찾아 방화벽을 수정, restorecon으로 SELinux 라벨을 복구해 약 1분 내 장애 감지를 달성.
02
GitHub Push → Notion 자동 동기화 구축
GitHub Actions · Node.js · Notion API | blog ↗
›
상황
GitHub에 Markdown으로 문서를 관리했지만 원본만으로는 가독성이 떨어졌음. push 시 Notion 페이지가 자동 생성·갱신되도록 동기화 구조를 구축.
원인
Actions가 생성한 commit이 다시 워크플로를 트리거해 무한 실행. frontmatter의 notion_page_id 미반영으로 수정 시마다 새 페이지가 생성되고, Notion API는 본문 일괄 교체 엔드포인트가 없어 블록을 직접 갱신해야 했음.
해결
commit 메시지에 [skip ci]를 붙여 무한 루프 차단, Actions가 page_id를 commit back하도록 구성. git diff status(A·M·D·R)로 생성·수정·삭제·이동을 분기 처리해 push 후 약 30초~1분 내 Notion 반영을 달성.
03
[프로그래머스] 택배 상자 꺼내기
Algorithm · Java | blog ↗
›
상황
2차원 배열로 지그재그 구조를 직접 구현했으나, 배열 크기 계산과 층마다 방향 전환 처리가 번거로워 더 나은 방법을 탐색.
원인
배열을 직접 생성하면 불필요한 메모리 사용과 순회가 발생. 수학적으로 위치를 바로 계산할 수 있음을 인식.
해결
상자 번호로 행·열 위치를 직접 계산하는 방식으로 전환. (num-1)/w로 행, (num-1)%w로 열을 구하고 홀수 행은 지그재그 보정 적용.
